做长文本打分时，我们往往只关心少数几个位置的 logits。分块处理输入之后，有些块甚至不包含任何需要打分的位置。这时，把 `logits_to_keep` 设成 `0`，看上去很像“这一块不需要输出”。

但在 Transformers **v5.12.1 的 `Qwen3_5ForCausalLM`** 中，整数 `0` 表示保留全部位置。它是这个接口的约定，不是“空集合”的另一种写法。下面只讨论这个确定版本的实现。

## 零为什么会变成全部

这个版本先得到完整的 `hidden_states`，再选择位置，最后调用 `lm_head`。整数参数走 `slice(-logits_to_keep, None)`；张量参数则直接作为索引使用。[官方源码](https://github.com/huggingface/transformers/blob/ddb849abe009d1089e6c691bfc897f27211c663c/src/transformers/models/qwen3_5/modeling_qwen3_5.py#L1675-L1678)

当参数是正整数 `k` 时，`-k:` 表示最后 `k` 个位置。但 `-0` 仍然是 `0`，因此 `-0:` 就是从第一个位置一直取到结尾。这也是该接口默认值为 `0` 时仍能返回完整 logits 的原因。

下面用合成张量展示索引语义，不加载模型：

```python
import torch

hidden = torch.zeros(1, 5, 3)  # [batch, positions, hidden_size]
keep = 0

all_rows = hidden[:, -keep:, :]              # 形状 [1, 5, 3]
empty_index = torch.empty(0, dtype=torch.long)
no_rows = hidden[:, empty_index, :]          # 形状 [1, 0, 3]
```

两个结果在位置维度上差了整整五行。数值 `0` 和长度为零的索引张量，表达的是不同操作。

## 没有目标位置时，传空索引

在不传 `labels`、只读取 logits 的评分调用中，没有目标位置的块可以使用空的 `torch.long` 索引张量；有目标位置的块则传入那些位置的索引。索引还要放在与被索引张量兼容的设备上，不能只检查 Python 层面的列表是否为空。若同时计算 loss，还需要按对应接口对齐 `labels`，不能把空索引或裁剪后的位置直接与完整标签配对。

假设隐藏状态形状为 `[B, L, H]`，词表大小为 `V`。选择 `M` 个位置后，输出层处理的是 `[B, M, H]`，返回 `[B, M, V]`。空索引对应 `M=0`。这里减少的是**序列位置**，没有裁剪词表；每个被保留的位置仍然需要完整的词表分布。

如果在外层封装里把“空列表”统一转成整数 `0`，就会把原本不同的语义合并掉。这个转换可能不报错，输出的 dtype 和最后一维也都正常，只有位置维度暴露出问题。

索引发生在哪里也很重要。在模型返回完整 logits 之后再切片，会改变结果的形状，但已经完成的输出层计算不会撤销。这里的实现先选择隐藏状态的行，再做词表投影。因此，除了检查输出形状，还要确认选择确实发生在输出层之前。

## 在输出边界检查形状

我会把需要打分的位置显式保存下来，并检查输出行数是否与索引数量一致。零个目标位置就应当得到零行输出，不能接受“多算一些再忽略”作为默认行为，否则优化是否生效很难确认。

对于分块评分，索引还必须是**当前块内的位置**。全局位置不能直接拿去索引局部 `hidden_states`；而目标 token 对应的预测行通常还需要向前移一位。行数正确，只说明数量对了，并不说明取到了正确的位置。

最后，空 logits 不代表这一块没有计算。主干仍然要消费输入，并在启用缓存时更新模型状态；这里跳过的是不需要的输出位置。是否减少峰值显存或端到端耗时，应在实际路径上分别检查，不能从一个空张量直接推算。

这类小优化值得先读一下接口的实际索引分支：默认值、空值和零值，未必指向同一件事。
